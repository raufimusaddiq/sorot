## What changed
- **Backend**: Spring Boot (Java 17) replaced by Bun/TypeScript in `backend/`
  (`bun:sqlite`, zero runtime deps). Same routes, JSON shapes and DB file;
  `backend/src/db.ts` migrates pre-ALTER databases.
- **Monorepo**: root Bun workspace (`backend` + `frontend`, one `bun.lock`,
  `linker = "hoisted"` for Next/Jest).
- **Static UI**: Next `output: 'export'` → `frontend/out`, served by the backend
  on :8080 (SPA fallback, immutable `_next/static`). One Docker image;
  `start.ps1 -Dev` adds hot-reload UI on :3000. `.env.local` → `.env.development`
  so prod builds stay same-origin.
- **Fixes found while porting/testing**
  - backend: stale-object save could flip CANCELLED back to RUNNING; `.part`
    cleanup deleted other jobs' downloads; cancel now kills the child process;
    retry reuses a finished download; Bun idle timeout raised to 255 s.
  - frontend: polling not resumed after reload; QUEUED not treated as active
    (code looked for non-existent `PENDING`); CANCELLED jobs polled forever.
  - ai-pipeline: `generate_clip_title` gave a hashtag-only title when text
    opened with punctuation; date-dependent test in `test_discover.py`.
- **Removed**: Java backend, `frontend/package-lock.json`, dead `ai-pipeline/utils/`.

## Part 3 — face-tracking reframe; OpenCV pin
Captions merged into `master` (`68bef0d`). Push to origin was blocked by auto
mode — user to run `git push origin master`.

- New `ai-pipeline/reframe.py`: 2 fps samples → faces (MediaPipe if present,
  else Haar) → per-frame centre (group if it fits the 9:16 window, else largest
  face) → hysteresis track (move only after 2 samples > 0.08 away) → ffmpeg
  `crop` x-expression; re-timed onto the silence-trimmed timeline. Modes
  `face` (default, centre fallback), `center`, `blur` (filter_complex fill).
- render.py `--reframe`; backend `REFRAME_MODE` → `--reframe`.
- **Bug found on real footage**: `requirements.txt` had no OpenCV upper bound;
  today's rebuild pulled OpenCV 5.0, which has no `CascadeClassifier`, so face
  detection (scoring + reframe) silently failed in Docker. Pinned `<5`; image
  rebuilt and verified (cv2 4.14, CascadeClassifier present).
- Real clip (Portal Ghaib, 30 s): centre crop showed logo + empty table; face
  mode followed guest → host with 7 crop segments.

## Part 4 — scoring face detection fix
Pushed `master` to origin (`e1a610d`). Then fixed scoring's face presence
(user approved; this shifts scores/tiers):

- Frames are decoded at 640 px; full-size `face_gray` is kept only near face
  check times, analysis copies downscaled to the calibrated 224 px (memory
  unchanged; motion values unchanged on the test clip).
- 5 face checks per segment (10–90 %), strict Haar (`minNeighbors=8`,
  `minSize=40`), **majority vote** (≥3 of 5). Calibration in the Docker image:
  per-frame Haar fired on 3–13/30 frames of a synthetic no-face video at every
  setting tried, so a single hit can't be trusted.
- Real clip: before `faces` 0.0/0.7/0.0 (3×10 s); after, 5 of 6 five-second
  segments detect faces (miss = wide opening shot); no-face video 0.0 on all.
- Python 421/421 (99.46%).
- Cost on 10 min of real footage (20 candidates): extraction 16.6 s → 18.1 s (+9%), frame memory 67 → 90 MB.
